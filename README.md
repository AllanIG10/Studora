# Studora

A student-management app built with React, Vite, Express, and MongoDB.

## Requirements

- Node.js 20.19+ (or 22.12+)
- MongoDB running locally, or a MongoDB Atlas connection string

## Setup

1. Install dependencies:

   ```sh
   npm install
   ```

2. Create a `.env` file in the project root using `.env.example` as a template. Set:

   - `MONGODB_URI` to your MongoDB connection string.
   - `JWT_SECRET` to a private random value of at least 32 characters.
   - `ADMIN_EMAIL` and `ADMIN_PASSWORD` for the administrator account. Admin passwords must be at least 12 characters.

   Keep `.env` private and do not commit it. The API provisions the administrator from these settings when it starts.

3. Start the frontend and API:

   ```sh
   npm run dev
   ```

   Vite runs on its default development port and proxies `/api` requests to Express on port `5000`.

## Authentication

- Staff select **Staff** and sign in with `ADMIN_EMAIL` and `ADMIN_PASSWORD`.
- Students select **Student** and sign in with their student account.
- Students can register with their name, email, password, and an existing department.
- If an email matches an existing student record, the name and department must match that record.
- New student registrations remain pending and cannot sign in until an administrator approves them from **Pending Approvals**.
- Approval creates or links the student profile and activates the account. Rejected requests are removed and can be submitted again.
- Students have individual URLs for their profile, timetable, and results. Staff manage department-wide timetables and timetable pictures, plus student-specific exam results, from **Academic Records**.
- Staff can publish and manage college events and upload poster/invitation images from **College Events**. Students can see upcoming events and open their posters from **Next Event** in their portal.
- Existing student accounts without a status are migrated to active when the API starts.
- Admin management APIs require an administrator JWT. Tokens expire after 8 hours and are kept in the current browser session.
- Login, registration, and server errors are displayed in the page.

This project does not send email verification or password-reset messages. Add email verification before using public student registration in production.

## Deploy online with Render

The included `render.yaml` deploys the React app and Express API as one web service. The production server serves the Vite build and routes `/api` requests to the API.

1. Push this project to a GitHub repository.
2. Create a MongoDB Atlas database and copy its connection string. In Atlas Network Access, allow connections from Render; Render's free service uses changing outbound IPs, so `0.0.0.0/0` may be required. Use a strong, database-specific password.
3. In Render, choose **New → Blueprint**, connect the GitHub repository, and deploy. Render reads `render.yaml`.
4. Enter these values when prompted:
   - `MONGODB_URI`: your Atlas connection string, with the database name included.
   - `ADMIN_EMAIL`: the administrator sign-in email.
   - `ADMIN_PASSWORD`: a strong password of at least 12 characters.
   `JWT_SECRET` is generated by Render. Do not commit any of these secrets or put them in the frontend.
5. Open the Render URL after the service is healthy. The same URL serves the app and its `/api`.

The free web service may sleep when idle and take a little time to wake up. Keep MongoDB credentials private.

## Deploy frontend to Netlify

To use a Netlify domain for the frontend, deploy the API separately on Render and keep MongoDB on Atlas:

1. Deploy the API using the Render Blueprint above. Set `MONGODB_URI`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and the generated `JWT_SECRET`.
2. In Netlify, choose **Add new site → Import an existing project** and select this GitHub repository. The included `netlify.toml` configures the build and SPA routes.
3. In the Netlify site environment variables, set `VITE_API_URL` to the Render API origin, for example `https://studora-api.onrender.com` (no trailing slash). Trigger a new deploy so the URL is included in the frontend build.
4. Add `FRONTEND_ORIGIN` to the Render service environment variables with the Netlify site origin, for example `https://your-site.netlify.app`, and redeploy the API. Use only the origin, without a path or trailing slash.

The Netlify site serves the React app; API requests and database access run through Render and Atlas. Never put database credentials or `JWT_SECRET` in Netlify's `VITE_` variables.
